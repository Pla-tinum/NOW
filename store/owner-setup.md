# What Valentyn needs to connect for the first paid mobile release

The app uses `com.valentynshemeiko.now` on both platforms. Do not register another bundle/package ID without changing the native projects and store setup together.

1. Create personal Apple Developer and Google Play Console accounts under the legal name **Valentyn Shemeiko**. Set the public Google Play developer name to **NOW** and the public support email to **aloe.vera225@yahoo.com**. Complete identity, tax, banking and paid-app agreements in the consoles.
2. Create the Android app and iOS app with the ID above. Create `now_plus_monthly` and `now_business_monthly` as monthly subscriptions and `listing_boost` as a consumable in-app product on both platforms. Connect products and store credentials to a RevenueCat project. Set the two public SDK keys at mobile build time and its **secret** API key only in Railway. Configure entitlements named `now_plus` and `now_business` and verify the identifiers returned by the RevenueCat subscriber API. Store purchases stay disabled until real sandbox tests pass.
3. Create Android and iOS apps in AdMob. Set up its UMP privacy message and the platform-specific app and banner unit IDs. Run `npm run sync:mobile` with the six build environment variables listed in `npm run check:store`. Replace demo IDs before a release build. Use test ads on devices first, then update Privacy/Data Safety disclosures and enable the server flag only after consent tests pass.
4. Supply signing access in the developer consoles. Google Play App Signing still needs a private upload key to create a signed AAB. iOS archive/TestFlight needs an Apple team, certificate and provisioning profile through Xcode or an authorized macOS build service. The unsigned projects and artwork are committed; no private signing material belongs in GitHub.
5. Verify StoreKit/Play Billing on devices or the official sandbox: initial purchase, subscription renewal, cancellation, expiration, refund, restore on a second installation, Boost consumption and account deletion with a subscription. Verify the actual localized store prices before submission. Capture screenshots from those final builds, complete both store disclosure/rating forms and run TestFlight / Google closed testing.

The source and public copy can be prepared now. The SDK keys, store products, AdMob identifiers, signed archives and live transaction results cannot be generated before these accounts exist.
