# What Valentyn needs to connect for the first paid mobile release

The app uses `com.valentynshemeiko.now` on both platforms. Do not register another bundle/package ID without changing the native projects and store setup together.

1. Create personal Apple Developer and Google Play Console accounts under the legal name **Valentyn Shemeiko**. Set the public Google Play developer name to **NOW** and the public support email to **aloe.vera225@yahoo.com**. Complete identity, tax, banking and paid-app agreements in the consoles.
2. Create the Android app and iOS app with the ID above. Create `now_plus_monthly` (59 NOK/month) and `now_business_monthly` (130 NOK/month) as monthly subscriptions, and `listing_boost` (19 NOK) as a consumable in-app product on both platforms. Put the two subscriptions in one upgrade/downgrade group on App Store Connect. Connect products and store credentials to a RevenueCat project. Attach the subscriptions to entitlements `now_plus` and `now_business`; do **not** attach consumable Boost to a permanent entitlement. Provide the RevenueCat iOS and Android **public SDK keys** at build time (`REVENUECAT_IOS_PUBLIC_KEY`, `REVENUECAT_ANDROID_PUBLIC_KEY`). Store the RevenueCat **secret** v1 API key as `REVENUECAT_SECRET_API_KEY` only in Railway. Verify the subscriber API's `subscriptions`, `entitlements`, `purchase_date` and `non_subscriptions` on sandbox receipts. Keep `STORE_BILLING_ENABLED` absent/false until sandbox and review-device checks pass.
3. Create Android and iOS apps in AdMob. Supply each platform's App ID (`ADMOB_IOS_APP_ID`, `ADMOB_ANDROID_APP_ID`) and banner unit ID (`ADMOB_IOS_BANNER_UNIT_ID`, `ADMOB_ANDROID_BANNER_UNIT_ID`). Set up the UMP consent/privacy message and test the consent form on iOS. Run `npm run sync:mobile` with these four identifiers and the two RevenueCat public keys, then `npm run check:store`. Replace demo IDs before a release build. Only safe feed/explore/banner placements are prepared; no ads in chat, message send, listing creation or listing detail. Paid subscribers must see no ads. Leave live ad serving disabled until the final privacy disclosures, consent checks and real unit IDs are ready.
4. Supply signing access in the developer consoles. Google Play App Signing still needs a private upload key to create a signed AAB. iOS archive/TestFlight needs an Apple team, certificate and provisioning profile through Xcode or an authorized macOS build service. The unsigned projects and artwork are committed; no private signing material belongs in GitHub.
5. Verify StoreKit/Play Billing on devices or the official sandbox: initial purchase, subscription renewal, cancellation, expiration, refund, restore on a second installation, Boost consumption and account deletion with a subscription. Verify the actual localized store prices before submission. Capture screenshots from those final builds, complete both store disclosure/rating forms and run TestFlight / Google closed testing.

The source and public copy can be prepared now. The SDK keys, store products, AdMob identifiers, signed archives and live transaction results cannot be generated before these accounts exist.

## Data to send back after account setup

Apple: Team ID, App Store Connect app/bundle ID, subscription group ID, the three created Product IDs, localized Norwegian prices and the App Store Connect API key credentials for RevenueCat (issuer ID, key ID and private key through a secure channel, not GitHub). RevenueCat: project/app identifiers, iOS/Android public SDK keys, secret v1 REST API key for Railway, confirmation of the two entitlement mappings and store connections. AdMob: iOS/Android App IDs and banner ad unit IDs, UMP privacy message status. Android later needs the Google Play service account connection to RevenueCat. Private keys and credentials must never be committed to the repository.
